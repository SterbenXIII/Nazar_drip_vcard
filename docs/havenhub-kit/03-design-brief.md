# Бриф дизайн-етапу

## Мета

Дати відвідувачу змогу за кілька секунд зрозуміти, для кого HAVENHUB, де центр, як звернутися й що відбувається далі. Тон спокійний, без тиску та драматичних «до/після» образів.

## Концепти до коду

`build-web-apps:frontend-app-builder` вимагає спершу створити повний візуальний концепт, потім реалізовувати схвалений дизайн. Показати дві цілісні системи на **однаковому реальному тексті**: A — теперішні navy/teal; B — стриманий бордовий акцент, який сподобався замовнику. В обох — 2–3 пари шрифтів з українською кирилицею, основний текст 16–18 px на desktop і читабельний mobile, чіткі кнопки/focus. Не вирішувати вибір лише за hero: потрібні секції з довгим текстом, списками, CTA, контактним фіналом і мобільний екран.

Підготувати координовані макети для: 1) hero + два шляхи, 2) напрями + формати, 3) програма + перший контакт, 4) родина + умови, 5) контакт + footer, 6) допоміжна сторінка + 320 px mobile. Текст і кнопки лишаються HTML/CSS у реалізації. Макети не стають джерелом нових фактів або доказом реальних приміщень.

## Система й перевірка

- Контейнери, відступи, типографічна шкала, кнопки, меню, посилання, секції, фото/підпис фіксуються після схвалення макетів у короткому design-token документі.
- Без повторюваних карток для кожного абзацу, автоматичних каруселей, рейтингів і лічильників. Фото не замінюють зміст.
- Мобільний порядок: заголовок → текст → CTA → ілюстрація → підпис. Перевірити 320 px, 200% browser zoom, довгі українські слова, клавіатуру, контраст і reduced motion.
- Після реалізації порівняти accepted concept із останнім browser screenshot на desktop/mobile, внести правки до відповідності, тоді зафіксувати QA evidence.

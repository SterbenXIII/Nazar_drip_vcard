## Продуктові рішення

- П'ять сторінок: повна головна та чотири допоміжні. Лише `/` індексується після release gate.
- У default build допоміжних маршрутів фізично немає. У staging вони доступні тільки після входу і мають `noindex`.
- Незавершена форма не показується як доступний спосіб звернення; телефон і Telegram залишаються.
- Немає цін, відгуків, профілів працівників, міських SEO сторінок, FAQ заглушок і статистичних бейджів без підтверджених даних.
- Старий `apps/web` і його SEO/форми поза обсягом. B0 окремо потребуватиме власника API контракту; зміни backend не виконувати у frontend потоці.

## Рішення, потрібні до production

| Питання | Хто підтверджує | Вплив, якщо немає відповіді |
| --- | --- | --- |
| Який формат доступний клієнтам поза Львівщиною? | Замовник | Не писати «послуги по всій Україні» як конкретну пропозицію |
| Чи належить і використовується `HavenHub.com`? Який канонічний HTTPS host? | Власник домену | Немає canonical, sitemap і public index build |
| Оригінал логотипа, ліцензія і фінальна назва написання | Замовник | Тимчасовий текстовий знак |
| Що означає «300–400+ пройшли курс»; період, записи, визначення результату? | Замовник/контент owner | Не публікувати число або «повернулися до повноцінного життя» |
| Медичні виконавці, кваліфікації, межі детоксикації, ПТСР, методів; чи 5 психологів доступні зараз? | Замовник/фаховий reviewer | Лише обережні перевірені загальні формулювання |
| Правила конфіденційності, строки зберігання заявок, коло доступу до бот-чату | Власник процесу B0 | Форма лишається вимкненою |
| Права на фото, оригінал чи ліцензія | Правовласник | Сторінка без фото або лише маркований protected staging |
| Остаточний варіант кольору й шрифтів | Замовник після порівняння | Не фіксувати тему в реалізації як схвалену |

## Зміни до специфікації

Відповіді заносити до реєстру тверджень із датою, джерелом, точним публічним формулюванням та відповідальним. При новому факті оновити spec, план і відповідний acceptance тест до зміни copy. Для медичних і вимірюваних тверджень коментар у месенджері є джерелом брифу, але не доказом результату.
